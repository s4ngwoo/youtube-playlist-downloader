# 동시 다운로드 가이드

이 앱은 트랙 작업을 **1–8개**까지 한꺼번에 돌릴 수 있습니다(**기본값: 3**). 숫자를 올려도 전체 시간이 **배수로** 줄지 않는 경우가 많습니다.

## “동시 다운로드”가 하는 일

동시 슬롯 하나 = 트랙 하나당 **yt-dlp 전체 작업**:

1. YouTube에서 미디어 받기  
2. 오디오 추출·변환 (FFmpeg)  
3. 썸네일·메타데이터 임베드  

즉 “받기만 N배”가 아니라 **받기 + 후처리** 파이프라인을 몇 개 병렬로 둘지입니다.

## 3이 1보다 체감이 비슷한 이유

- **회선은 하나**입니다. 스트림이 늘면 대역폭을 나눠 쓰는 경우가 많습니다.  
- **YouTube/CDN**이 같은 네트워크의 다중 연결을 조절할 수 있습니다.  
- 받은 뒤 **추출·앨범아트·태그**는 CPU·디스크를 씁니다. FFmpeg가 여러 개면 서로 기다립니다.  
- **한 곡이 느리거나 실패**하면 세션 전체가 끝난 느낌이 늦어집니다.

남는 대역폭·CPU가 있을 때, 곡이 많고 받기 비중이 클 때 이점이 큽니다. 이미 회선/CPU가 바쁘면 이점이 작습니다.

## 권장 설정

| 상황 | 권장 |
| :--- | :--- |
| 일반 사용 | **2–3** (기본 **3**이면 충분) |
| 느린 Wi‑Fi·불안정·제한 회선 | **1–2** (안정성 우선, 오류 감소) |
| 빠른 유선 + 여유 CPU, 긴 플레이리스트 | **3–5** — 버벅이면 낮추기 |
| 6–8 | CPU/디스크가 여유 있을 때만; 실패·소음 늘 수 있음 |

**팁:** 느리거나 실패할 때는 동시 개수보다 상단 **yt-dlp 업데이트**·하단 **환경 진단**(FFmpeg/Deno)을 먼저 확인하세요.
